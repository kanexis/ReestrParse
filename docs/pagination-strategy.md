# Стратегия пагинации

## Проблема старой реализации

Старый crawler искал нужную организацию на странице, открывал её в том же tab, затем делал `Back()`. ЕИАС восстанавливал каталог с первой страницы, поэтому для организаций со страниц 2/3/... пагинация проходилась повторно.

## Текущая стратегия

### Catalog phase

1. Применить регион/сферу/форму.
2. Отдельно нажать `#searchBtn`.
3. На каждой странице прочитать текущий `ASPxGridView2`.
4. Одновременно попытаться получить DevExpress row key и сформировать прямой `DetailUrl`.
5. Перейти к следующей странице только через актуальный отображаемый pager.
6. Не открывать карточки организаций во время catalog phase.

Пагинация выполняется ровно один раз.

### Details phase

После завершения каталога browser position больше не имеет значения. `OrganizationReference[]` передаётся worker pool, а каждый worker открывает карточку напрямую по `DetailUrl`.

Таким образом сложность details phase больше не зависит от номера страницы, на которой организация находилась в каталоге.

## Почему catalog не параллельный

DevExpress pager — состояние одной web session. Параллельный доступ нескольких потоков к одному `IWebDriver` создаёт callback/stale races.

Параллельность переносится туда, где задачи независимы: обработка уже найденных карточек организаций.
